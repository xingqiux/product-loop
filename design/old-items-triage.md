# 旧队列里还开着的事在新方案里的去处

本文逐条写出旧 skill 队列里还开着的事，在新方案里落到哪里。旧流程已经停下，这些事不再回到旧队列。

旧队列里还开着的有十件。其中五件的子项是各自独立的问题，本文把子项拆开编号：A 到 D 组共二十三条，F 组十一条。E 组是另外五件，加上第 29 条。第 29 条不在队列里，来自用户的原话。

依据的材料有四类：

- 新方案「软件设计」00 到 14，按 9 月 28 日零点二十分的版本。另一个会话正在改这组文档，本文引用的节号已按这一版核对。
- 旧 skill 冻结在 `v1-final` 的代码：`build-report.py`、`land.py`、`writing.py`、`check-reply.py`、报告模板和覆盖表。
- 落地第 13、14、17 轮的评审记录和计划。
- 旧主线、决定表和队列数据。

去处分三种：

| 去处 | 含义 |
| --- | --- |
| 已覆盖 | 新方案已经写了这件事的做法，引用写到文档和节 |
| 要补进新方案 | 新方案还没写，或者只写了一半。表里给出要补的原文和位置 |
| 不再适用 | 产生这件事的机制在新方案里已经去掉，或者用户定了不做 |

界面上的行为另写「形式」，分两种：

- 场景的一步：用户完成任务时一定会走到的操作。写进这个软件主线的场景 S1 到 S12，使用代码每次都走。
- 覆盖表的一行：状态、边界和偏好这类细节。写进「06 工作台」第八节的对照表，第二期验收时逐行对照。这个软件自己的覆盖表里，每一行也要写被哪个场景用到。没被用到的行，收尾使用轮时由规则 `use.leave` 拦截（「07 校验」第四节）。

A、B、C 三组都是评审的建议，当时进了队列，之后没有一条被拿出来。决定 136 已经改成当轮收口：要么修掉，要么写明不修的理由，不再进队列。「04 命令行」第十一节已照此写。本文就是这三组的逐条裁决。

下文的「03 第二节」指「03 数据模型」第二节，其余文档同理。
