# 借鉴的公开 skill

产品循环只借方法，自己写，不依赖别人的 skill。一个 skill 调用另一个 skill 以后，回不到原来的流程，官方至今没有修这个问题。

2026 年 9 月查了四个目的相近的公开 skill。每个写清楚拿了什么、没拿什么、为什么。

## 一、product-llc/claude-skills 里的 ux-audit

作者是 Alex Zapadenko。它的定位是只找问题，不排优先级，因为排优先级要懂业务。

拿了：

- 每一步先写该看到什么，再写动作。写不出的那一步，本身就是一条发现。这条进了「使用代码」里的 `expect`。
- 每条发现写我看了什么，例如截图、文件、命令输出。没看过的不写。
- 环境造成的假问题，例如无头浏览器的剪贴板和焦点，单独标成环境，不当产品问题。这条进了「使用代码」的常见坑。

没拿：

- 严重度 0 到 4 打分。用户明确不要数字，而且分数是给排序用的。我们的排序规则已经有了：主流程上的先。
- 报告末尾的怎么重跑。加过一次，用户说对开发者没必要，删了。
- 不排优先级。它给外部审计者用，审计者不懂业务。我们在项目里，主线就是业务，所以要给选项让用户选。
- 只读不改产品。它是审计，我们的结果是改到位。

## 二、wonjyou/design-audit

它有六类检查：视觉、可用性启发式加无障碍、界面模式、人的因素、文案、信息架构。另有四级严重度，最后一节写值得保留的优点。

拿了：

- 文案单独一类。这条进了「检查的做法」里交互一致性的文案提醒，查符号、英文标识和说明句。
- 界面模式里的：给机器用的选项露给了人。这条进了必要性的提醒。

没拿：

- 六类分开写报告。用户每一屏看到的是一个整体，按类拆开会把同一个元素拆到三处。我们按屏走，问题按屏记。
- 值得保留的优点一节。用户要的是要改什么，不要表扬。
- 四级严重度。同上，不要数字和等级。

## 三、jezweb 的 design-review

它有七个维度：布局间距、字体、颜色对比、层级、组件一致性、交互、响应式。另有一张不专业的标志表。

拿了：

- 不专业的标志这个思路：对不齐、间距不一致、文字被切、占位文字留在页面上。这条进了交互一致性的提醒，也进了「直接修」这一类，例如文字被切掉半个。
- 颜色要有含义，没含义的颜色是噪音，全灰又像禁用。这条进了交互一致性的提醒。

没拿：

- 按七个维度出报告。理由同上一节。

## 四、vercel-labs 的 web-design-guidelines

它有一百多条规则，例如焦点样式、动效时长、对比度。

拿了：没有直接拿。它是给写 CSS 的人用的检查表，粒度在像素和毫秒。我们的问题在这个东西该不该存在，还没到那一层。

留着：主流程全通、问题清零以后，如果要做无障碍和细节打磨，可以拿它当清单。

## 与它们的差别

它们都是找完交清单。产品循环的结果是改到位，并用改前改后证明。所以多了三样：

- 请求分类：直接修、先问再改、提升、不做。
- 选项的写法：差别、理由、代价、适用场景。
- 改完重跑同一个场景，出改前改后两张图。

少了一样：任何形式的分数和统计。
