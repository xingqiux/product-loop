# 迁移的做法

还在用旧 skill 的项目，按这里的步骤迁移到新的软件。迁移用的 `ploop doctor` 是过渡命令，2026-12-31 删除。到期以后，这份文件也不再需要。
迁移分三步：迁移检查、确认、执行。只有确认这一步要你判断。

## 一、迁移检查

在项目根目录运行 `ploop doctor`。旧文件在项目根以外时，用 `ploop doctor --from <目录>` 指明。

迁移检查只读旧文件，不改项目里原有的文件。它把要判断的内容写进 `.product-loop/migrate/`：

- `队列迁移对照.md`：每件旧的队列事项一行，写着建议的新状态。
- `决定迁移对照.md`：每条旧决定一行，表后列出没有读的旧行。
- `pages/`：每一页旧页面一份，里面是转成当前格式的页面数据。仍被拦截的，旁边有同名的 `.报错.md`。
- `其他确认.md`：别的检查项要确认的地方，一条一行。

输出里以「确认：」开头的行，就是要你处理的地方。

## 二、确认

逐项处理「确认：」开头的行，改的是 `migrate/` 里的文件。改完再运行一次 `ploop doctor`，直到不再列出要确认的地方。
已经写好的文件，迁移检查不会覆盖，你改过的内容就是导入的依据。

### 队列迁移对照

- 逐行核对新状态和各格。核对完在「确认」一格写「是」。
- 新状态只写待办、等待、已完成、已取消。
- 「待核对」的一行，用 git 的提交记录查这件事做没做完。做完的写已完成，并在完成证据里写提交号。没做完的写待办。
- 已完成要写完成证据，等待要写依赖，已取消要写状态说明。
- 「阶段」一格写构思、使用、检查、落地、提升之一。
- 「提出」一格写用户、AI、评审或别的项目。
- 日期写成 2026-09-20 这样。
- 不要删行，也不要加行。旧文件里的每一件都要在表里。

### 决定迁移对照

- 补齐缺的日期。字里写着日期的，照它补。查不到的，写这条决定所在那个阶段的日期。
- 已作废的一行，写明被哪一条推翻，只写一个编号。
- 决定的一行要写案例。以后再说的一行不用。
- 核对完在「确认」一格写「是」。
- 表后没有读的旧行，要导入的抄进表里，不导入的写明去处。处理完把 `[ ]` 改成 `[x]`。

### 旧页面

- 有 `.报错.md` 的一页，按报错改这一份里的页面数据。改的是转换后的数据，旧文件不动。
- 「阶段名」空着的一页，是只有网页的快照，看网页的内容定阶段名。
- 同一个阶段的几页阶段名不同时，改成同一个阶段名。确实是两个阶段的，改迁移文件里「归到的阶段」这一格，把它们分开。
- 转不了的一页，「页面数据」是空的，照「转不了的原因」重写这一页的数据。
- 引用的截图找不到的，改页面数据里的路径，指到 walk/ 下确实有的图。
- 这一阶段不能写的发现问题和提升，转换时已挪进疑问，标签写原来区块的名字。不用再挪。
- 报错要补的内容原页面上没有，补了就是编造。这时把这一份的「快照」改成 true，按网页存成快照。只有 walk/ 下有同名网页的页才能这样做。

### 其他确认和仓库类别

- `其他确认.md` 的每一条看过、处理完以后，把 `[ ]` 改成 `[x]`。
- 看不出仓库是自己的还是共用的，要问用户。用户答了以后，运行 `ploop doctor --repo 自己的` 或者 `ploop doctor --repo 共用的`。

## 三、执行

没有要确认的地方以后，运行 `ploop doctor --fix`，看不出仓库类别时同样带上 `--repo`。命令依次做这几件事：

1. 在集中存储里登记项目。
2. 把旧文件打成一个归档包，交给后端存起来。
3. 截图按哈希上传，其余数据在一个事务里导入。
4. 核对页面、阶段、决定、队列事项和截图的数量，对上了才标记迁移完成。
5. 写 `project.json`、`主线.md`、`决定.md` 和忽略规则。
6. 清理旧文件和 `migrate/`。已提交进 git 的旧文件，用 git 删除，单独提交一次。

任何一步失败，命令停下并列出原因，不清理旧文件。按原因改好 `migrate/` 里的文件，再运行一次 `ploop doctor --fix`，它从停下的那一步接着做。

迁移完成以后，运行 `ploop` 看项目的状态。旧的阶段都在第 1 版，下一次开始一个阶段就进入第 2 版。
原样的旧文件一直留在集中存储的归档包里。
