```text
产品循环的命令行

  -h, --help                显示帮助

  round                     阶段的开始、查看和收尾

  lint                      写作校验；会话回复发出前的自查
  skill                     报 skill 的问题，维护者处理

维护命令
  backend                   后端的启停和查看
  backup                    备份和恢复

  storage                   查看集中存储的占用
  setup                     安装或升级命令行

过渡命令（2026-12-31 删除）
  doctor                    迁移检查（2026-12-31 删除）

细节
  不写命令，等同 ploop status。
  维护命令和过渡命令默认不列，运行 ploop --help --all 列出全部。
  输出里的时间一律是北京时间。
  文件夹名里的时间是 UTC，以 Z 结尾。

阶段的四步
  开始      ploop round start <阶段名>
  给出信息  ploop page present
  回复      ploop reply wait
  处理      ploop reply handle

环境变量
  PLOOP_HOME           集中存储的位置；不写用 ~/.product-loop
  PLOOP_PORT           后端的端口；默认 4731，写 0 由系统分配
  PLOOP_SESSION        会话标识，可不写；写了冲突时能看到是哪个会话
  PLOOP_BROWSER        ploop open 用的程序；不写用系统的
  PLOOP_TIME_MACHINE   写 off 关掉每天的 Time Machine 检查，测试用
  PLOOP_LAUNCHCTL      backend autostart 用的 launchctl，测试用
  PLOOP_BACKEND_ENTRY  后端的入口文件，开发用；不写用 backend.mjs
  PLOOP_USE_OUT        use run 设好的输出目录，不用自己设

  0    成功，看「下一步」

  2    用法错误：参数缺失或取值不对，看 --help
  3    冲突：状态不允许，例如另一页在等、别的会话改过主线，按报错里的命令先处理冲突
  4    找不到：项目、阶段、事项、文件不存在，检查编号和路径
  5    后端连不上或起不来，按报错里的步骤排查
  6    要先做迁移检查：项目停在旧版本的 skill，运行 ploop doctor
  7    还在等：到了时限，用户还没提交，再运行一次同样的命令
  8    等的那一页已撤回或已被新的一页代替，运行 ploop status
  130  被中断
```

## ploop init

```text
ploop init

在当前项目开工

用法
  ploop init [选项]

选项
  --repo <仓库>   仓库归谁，第一次必填（取值：自己的、共用的）
  --hook <是|否>  会话开始的钩子：是=写入，否=撤掉（取值：是、否）
  --json          输出机读的结果

细节
  登记项目，建项目缓存。
  按仓库是谁的写忽略规则。
  自己的仓库写进 .gitignore。
  共用的仓库写进 .git/info/exclude。
  写「是」写入会话开始的钩子，写「否」撤掉。
  撤掉时只删 ploop 写的那一条。
  不写 --hook，第一次开工在终端里会问。
  不在终端里就不写，以后重跑不再问。
  写入的是 ploop 的绝对路径。
  路径变了，要重跑 ploop init --hook 是。

会拦截的情况
  第一次开工没写 --repo                       问用户仓库是自己的还是共用的，带上 --repo 重跑
  共用的仓库不在 git 里                       改写 --repo 自己的
  项目缓存还在，集中存储里没有登记这个目录    不用写 --repo，按缓存里的忽略规则重新登记，主线.md 和各阶段的文件保留
  在家目录下运行                              到项目的根目录下运行
  这里有旧 skill 的文件                       先运行 ploop doctor

读和写
  读  项目缓存的 project.json
  写  集中存储的项目和主线。项目缓存的 project.json、README.md、主线.md。忽略规则文件。用户同意时，另写 .claude/settings.local.json。

例子
  ploop init --repo 自己的
  ploop init --repo 共用的
  ploop init --hook 是
  ploop init --hook 否

做完以后
  ploop round start 构思
```

```text
ploop round start <阶段名>

开始一个阶段

用法
  ploop round start <阶段名> [选项]

参数
  <阶段名>               构思、使用、检查、落地、提升之一

  --take <编号,…>        落地阶段定这一批，例如 Q12,Q15；不写拿全部待办

  项目停在旧版本的 skill                先运行 ploop doctor

  读  项目缓存的 project.json、主线.md
  写  集中存储的阶段和队列，项目缓存的工作区；主线.md 有改动先交成新修订
```

## ploop round close

```text
ploop round close

收尾一个阶段

用法
  ploop round close [选项]

选项
  --done <编号>=<证据>    这件事做完了，写明证据，例如 Q12=提交 3f2a9c1；可以写多次
  --return <编号>=<原因>  退回队列并写原因；写 Q15:构思=原因 就退到构思
  --summary <说明>        收尾说明，一句话写这个阶段做了什么
  --abort <原因>          放弃这个阶段，写原因；拿出的事退回待办，不要求给页
  --json                  输出机读的结果

细节
  检查这个阶段拿出来的事都有结果。
  落地阶段另查代码全部提交。
  --abort 放弃一个阶段；给用户看过更改以后不能放弃。

会拦截的情况
  拿出来的事还没有结果                   用 --done 或 --return 写明每件事的结果
  还有一页在等用户点                     先运行 ploop reply wait，或用 ploop page withdraw 撤回
  回复还有行没有处理                     先运行 ploop reply show，再用 ploop reply handle 处理
  用户对更改点了不认可，却写了 --done    改写成 --return <编号>:落地=<原因>

读和写
  读  项目缓存的 project.json、主线.md
  写  集中存储的阶段、队列

例子
  ploop round close
  ploop round close --abort "计划要改"
  ploop round close --done Q12="提交 3f2a9c1" --return Q15:构思="定义不对" --summary "修好了设置页"

做完以后
  按输出的「下一步」开始下一个阶段
```
