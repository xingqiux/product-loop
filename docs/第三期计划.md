# 第三期计划

第三期交付跨项目的部分，范围见「11 分期计划」第五节，页面见「06 工作台」第二节和第七节。
第四期（MCP）不做（决定 201）。重构本身不走产品循环的流程，做完在对话里说明并给截图（决定 200）。

做法：三组互不相干的活由子代理在各自的工作目录里同时做，合并时由主会话核对。
每组做完跑 `pnpm check` 和 `pnpm use` 再提交。要起浏览器的场景放进 `scripts/use/scenes/`。

## 一、切换

| # | 做什么 | 完成标准 |
| --- | --- | --- |
| 1 | 剩下六个项目迁移 | 每个项目 `ploop doctor` 没有要确认的地方，`ploop doctor --fix` 做完，项目出现在工作台上。旧文件进归档，能还原 |
| 2 | 旧正文移走 | `product-loop-bate` 从两个 skill 目录移到归档目录，`product-loop` 指向新正文 |

## 二、第三部分

| # | 做什么 | 完成标准 |
| --- | --- | --- |
| 3 | 所有项目的看板 `/` | 每个项目一行，有页在等的排最前，其余按最近改动排。每行写项目名和根目录最后一段、当前轮次和状态、在等的页（按钮）、五个阶段的队列件数和停了七天的件数、skill 版本（旧的标出并写 `ploop doctor`）、最近改动时间。顶上一行只写要用户动手的事。场景 S1 按它改写 |
| 4 | skill 的问题页 `/skill` 和三类信号 | 问题每条一行：项目、轮次、方面、类、状态，按下出展示卡片。`GET /skill/signals` 算出反复被拦截的规矩（十四天内次数最多的几条，写次数、项目数、最近一次原文）、停在旧版本的项目、停了很多天的事（进行中超过三天没变的轮次，待办或进行中超过七天没变的队列事项）。点一个项目的信号进到项目页。补场景 S11 |
| 5 | `ploop prime` 和会话开始的钩子 | `ploop prime` 在项目目录里输出十行以内的状态和下一步，不在项目里什么都不输出。`ploop init` 问过用户同意后，把会话开始时运行 `ploop prime` 写进项目的 `.claude/settings.local.json`，不同意就不写（决定 197） |
| 6 | 开机自动启动后端（可选） | `ploop backend autostart on` 装上 launchd 登录启动项，`off` 卸掉，`status` 查看。不运行这条命令就不装（决定 198）。测试只碰临时家目录 |

## 三、验收

1. 八个项目都在看板上，每个的版本、阶段、轮次、队列和实际一致。
2. 在另一个项目里用 `ploop skill report` 报一个问题，它出现在 skill 的问题页上，并走完新、已理解、已确认、已改几个状态。
3. 三类信号都用真实数据算出来，不是空的。
4. 装了开机启动时，重启电脑以后不运行任何命令，工作台的地址也能打开。
